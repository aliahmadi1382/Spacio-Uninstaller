# اسپاسیو | Spacio

![Spacio logo](assets/spacio-128.png)

برنامهٔ دسکتاپ ویندوز برای بررسی حجم فایل‌ها و پوشه‌ها، با رابط فارسی و انگلیسی.

نسخهٔ **۱.۷.۰** پس از حذف برنامه از داخل Spacio، صفحهٔ **باقی‌مانده‌های برنامه** را خودکار باز می‌کند: مسیر و حجم پوشهٔ نصب، داده‌ها و کش‌های مرتبط نمایش داده می‌شود. موارد دلخواه را انتخاب کنید، **مرور پاک‌سازی** را بزنید، در پیش‌نمایش تیک موارد موردنظر را بزنید و حذف را تأیید کنید. هیچ باقی‌مانده‌ای از قبل برای حذف انتخاب نمی‌شود؛ تنظیمات و اطلاعات حساب هم ممکن است در پوشهٔ داده‌ها باشند.

Spacio اطلاعات برنامه را پیش از اجرای حذف‌کننده نگه می‌دارد و برای بررسی خودکار، خروج موفق فرایند و حذف پایدار ثبت برنامه را بررسی می‌کند. اگر پنجرهٔ اولیه زود بسته شود، حذف لغو شود یا نتیجه روشن نباشد، موفقیت اعلام نمی‌کند. پس از اتمام واقعی، می‌توانید **حذف‌کننده تمام شده؛ بررسی باقی‌مانده‌ها** را بزنید؛ این گزینه فقط بررسی را شروع می‌کند. **بعداً؛ فقط توقف پیگیری** حذف‌کننده را نمی‌بندد. دکمهٔ **باقی‌مانده‌های آخرین حذف** در صفحهٔ برنامه‌ها/Cache، همین بررسی را در همان اجرای Spacio دوباره باز می‌کند.

فهرست به مسیرهای ثبت‌شده یا شناخته‌شده و پیشنهادهای با نام دقیق همان محصول محدود است. ارتباط موارد **احتمالی** تأیید نشده و موارد مشترک برچسب دارند؛ همهٔ مسیرهای سفارشی، حساب‌های دیگر یا باقی‌مانده‌های رجیستری پوشش داده نمی‌شوند. برای Notion، داده‌های Roaming و کش‌های آن جداگانه قابل بررسی‌اند. پس از حذف موارد انتخابی، همین فهرست دوباره تازه می‌شود؛ اسکن‌های ذخیره‌شده باقی می‌مانند.

نسخهٔ **۱.۶.۰** حذف کامل داده‌های انتخابی برنامه‌ها، از جمله زیرپوشه‌های AppData، را اضافه می‌کند. مورد را در جدول انتخاب کنید و **مرور حذف و کش‌های مرتبط** را بزنید؛ تمام محتوای قابل‌خواندن دوباره بررسی می‌شود. پس از دیدن جزئیات، تیک تأیید حذف داده‌ها و تیک حذف دائمی را بزنید. تنظیمات، اطلاعات حساب و تاریخچهٔ داخل همان پوشه هم حذف می‌شوند. پیوندها و مقصدشان نمایش داده می‌شوند؛ فقط خود پیوند حذف می‌شود و مقصد باقی می‌ماند. پوشه‌های دارای پیوند فقط از مسیر حذف دائمی قابل حذف‌اند.

برای برنامه‌های نصب‌شده مانند **Notion**، **اجرای حذف‌کنندهٔ برنامه** را بزنید. نصب پیش‌فرض پشتیبانی‌شدهٔ **Hermes Agent** نیز از روی لانچر و اطلاعات حذف‌کنندهٔ خودش شناسایی می‌شود؛ برای حذف برنامه و داده‌های Hermes، در حذف‌کنندهٔ بازشده **Full uninstall** را انتخاب و تأیید کنید. کش‌ها و داده‌های باقی‌مانده بررسی و تأیید جداگانه دارند. فایل قفل‌شده یا غیرقابل‌دسترسی با مسیر و دلیل خطا گزارش می‌شود؛ Spacio برنامه‌های باز را به‌زور نمی‌بندد و فایل‌های سیستم، کل پروفایل و اسکن‌های خودش را حذف نمی‌کند.

**پایش زنده:** برچسب **زنده · منتظر تغییرات** یعنی برنامه منتظر اعلان فایل‌سیستم است و اسکن انجام نمی‌دهد. اعلان‌های سریع دسته‌بندی می‌شوند؛ اعلان تکراریِ ریشه به‌تنهایی اسکن کامل راه نمی‌اندازد. پس از بررسی سنگین، بین کارهای خودکار فاصله می‌افتد و خطاهای متوالی با تأخیر بیشتر دوباره بررسی می‌شوند. اعتبارسنجی پنج‌دقیقه‌ای فقط همان پوشهٔ بازشده باقی است. دکمهٔ **توقف پایش / ادامهٔ پایش** پایین صفحه، پایش را برای همین اجرای برنامه متوقف یا فعال می‌کند؛ Refresh دستی و نتیجهٔ ذخیره‌شده باقی می‌مانند. پس از ادامه، فقط پوشهٔ فعلی اعتبارسنجی می‌شود. حرکت دائمی نوار بررسی، در نبود تغییر یا خطا، حالت عادیِ انتظار نیست.

فایل نصب فعلی برای ارسال به کاربران: **Spacio-1.7.0-Setup.exe** در [آخرین انتشار](https://github.com/aliahmadi1382/Spacio-Uninstaller/releases/latest).

از نسخهٔ **۱.۵.۱** فایل نصب **Setup** اضافه شده است. نصب به‌صورت پیش‌فرض آیکون سبز Spacio را روی دسکتاپ و در Start Menu می‌سازد. آپدیت داخل برنامه همچنان فعال است و اسکن‌های قبلی باقی می‌مانند.

مرور حذف هنگام تازه‌سازی خودکار هم قابل انتخاب است: کار پس‌زمینه لغو می‌شود و فقط فایل‌ها یا پوشه‌های انتخاب‌شده برای پیش‌نمایش دوباره خوانده می‌شوند. نتیجهٔ قدیمی کل درایو، حذف یک مورد سالم را برای همیشه غیرفعال نمی‌کند. تغییر پس از پیش‌نمایش همچنان حذف را متوقف می‌کند؛ موارد غیرقابل‌خواندن، سیستمی، ابری و پیوندهای ناشناخته محافظت می‌شوند. پنجرهٔ تأیید با ارتفاع نمایشگر تنظیم می‌شود و متن کامل خطا قابل خواندن و کپی است.

نسخهٔ **۱.۵.۰** صفحهٔ کامل **Cache** و **برنامه‌های نصب‌شده** را اضافه می‌کند. فایل یا پوشه را انتخاب کنید و **مرور حذف و کش‌های مرتبط** را بزنید: مسیر، حجم، نوع ارتباط و فهرست کامل محتوای شناسایی‌شده قبل از حذف نمایش داده می‌شود. **حذف دائمی** پیش‌فرض است و هر بار به تأیید جزئیات و پذیرش غیرقابل‌بازگردانی از سطل بازیافت نیاز دارد؛ می‌توانید آن را به انتقال به سطل بازیافت تغییر دهید. کش اضافی، مشترک و پوشهٔ احتمالی خودکار انتخاب نمی‌شوند.

صفحهٔ Cache مسیرهای شناخته‌شدهٔ کاربر فعلی را بررسی می‌کند: کش Chrome، Edge، Brave، Firefox، VS Code، Discord، Slack، Steam، کش رسانه‌ای مشترک Adobe و کش shaderهای DirectX/NVIDIA/AMD. پوشه‌های با نام `cache` یا `.cache` در اسکن بازشده فقط با برچسب **نیازمند بررسی** نمایش داده می‌شوند. این فهرست همهٔ کش‌های هر سیستم یا هر فایل را تضمین نمی‌کند؛ مسیرهای سفارشی، حساب‌های دیگر، داده‌های حساب/کوکی/رمز، کش نصب‌کننده‌ها و فایل‌های شخصی به‌عنوان کش شناخته‌شده حذف نمی‌شوند. پوشهٔ اصلی کش نگه داشته می‌شود و فقط محتوای مرورشده پاک می‌شود. کش‌های مشترک متعلق به یک فایل خاص نیستند؛ بازسازی آن‌ها ممکن است اجرای بعدی برنامه را کندتر کند.

برای برنامه‌ها، حذف‌کنندهٔ ثبت‌شدهٔ خود برنامه اجرا می‌شود؛ پس از پایان تأییدشدهٔ آن، صفحهٔ باقی‌مانده‌ها باز می‌شود و حذف داده‌ها/کش‌ها تأیید جداگانه می‌خواهد. برنامه‌های دسکتاپ ثبت‌شده فهرست می‌شوند؛ برنامه‌های دیگر از **تنظیمات برنامه‌های ویندوز** مدیریت می‌شوند. برنامهٔ باز یا فایل قفل‌شده خودکار بسته نمی‌شود و مورد ناموفق در گزارش می‌ماند. رجیستری پاک‌سازی نمی‌شود و ارتباط مسیرهای احتمالی قطعی تلقی نمی‌شود.

در نسخهٔ **۱.۴.۲** پایش خودکار هم فقط پوشهٔ بازشده و زیرپوشه‌هایش را دنبال می‌کند؛ حتی اگر نتیجهٔ آن از اسکن ذخیره‌شدهٔ کل درایو آمده باشد. بررسی شروع برنامه، بررسی دوره‌ای و جبران اعلان‌های ازدست‌رفته به همان پوشه محدودند. با ورود به پوشهٔ دیگری، بررسی خودکار قبلی لغو می‌شود. Refresh دستی نیز می‌تواند بررسی خودکار فعال را متوقف کند و مسیر کادر را تازه‌سازی کند. سایر بخش‌های اسکن ذخیره‌شده باقی می‌مانند و هنگام بازکردنشان بررسی می‌شوند.

در نسخهٔ **۱.۴.۱** بخش‌های **پوشه‌ها و فایل‌ها، فایل‌های بزرگ، فایل‌های قدیمی و نوع فایل‌ها** صفحهٔ کامل دارند. آن‌ها را از نوار کناری باز کنید، یا بالای جدول نمای کلی **نمایش در صفحهٔ کامل** را بزنید. جدول جای کارت‌ها و نقشه را می‌گیرد تا ردیف‌های بیشتری دیده شوند؛ جست‌وجو، فیلترها، به‌روزرسانی زنده و خروجی CSV در دسترس می‌مانند. با **بازگشت به نمای کلی** دوباره کارت‌ها و نقشه نمایش داده می‌شوند.

نسخهٔ **۱.۴** نتیجهٔ ذخیره‌شده را ابتدا باز می‌کند و سپس تغییرات فایل‌ها را در پس‌زمینه دنبال می‌کند: حذف، جابه‌جایی، اضافه‌شدن و تغییر حجم. Refresh جدول را خالی نمی‌کند. [آخرین نسخهٔ قابل حمل را دریافت کنید](https://github.com/aliahmadi1382/Spacio-Uninstaller/releases/latest). اسکن‌های کامل نسخهٔ ۱.۲ به بعد همچنان قابل استفاده‌اند.

در نسخهٔ **۱.۳.۲** صفحهٔ شروع حرکت پیوسته دارد: حلقه‌های چرخان، لوگوی شناور، نورهای سبز و ذرات متحرک. این صفحه هنگام آماده‌شدن برنامه و بارگذاری نتیجهٔ قبلی هم متحرک می‌ماند و پس از یک معرفی کوتاه وارد محیط اصلی می‌شود. آپدیت، نتایج اسکن و فایل‌های اسکن‌شدهٔ شما را پاک نمی‌کند؛ نسخهٔ جدید همان نتیجهٔ ذخیره‌شدهٔ قبلی را باز می‌کند.

## اجرا

روش پیشنهادی: فایل `Spacio-1.7.0-Setup.exe` را اجرا کنید، گزینهٔ میان‌بر دسکتاپ را نگه دارید و **نصب** را بزنید. مسیر نصب `%LOCALAPPDATA%\Programs\Spacio` است و Administrator لازم نیست. پیش از نصب مجدد یا حذف برنامه، Spacio را ببندید. Setup برنامه‌ها را اجباری نمی‌بندد و نسخهٔ قدیمی‌تر را روی نسخهٔ جدید نصب نمی‌کند. نصاب هم فارسی و انگلیسی دارد.

نسخهٔ قابل حمل نیز موجود است: ZIP را استخراج کنید و `Spacio.exe` را همراه `Spacio.exe.config` اجرا کنید. سیستم موردنیاز هر دو روش: Windows 10/11 نسخهٔ ۶۴ بیتی با .NET Framework 4.8. نصب و اجرای اولیه به اینترنت نیاز ندارد؛ دریافت آپدیت به اینترنت نیاز دارد. این نسخه هنوز امضای دیجیتال ناشر ندارد.

برای حذف خود Spacio از **Installed apps** ویندوز استفاده کنید. فقط فایل‌های مشخص برنامه، میان‌برهای متعلق به آن و ثبت نصب حذف می‌شوند؛ اسکن‌های `%LOCALAPPDATA%\Spacio\Scans`، زبان، فایل‌های شخصی و نسخه‌های بازگشت آپدیت حفظ می‌شوند. نصب مجدد نتیجه‌های قبلی را باز می‌کند.

1. از کلید بالای پنجره برای تغییر **فارسی / English** استفاده کنید. زبان انتخابی برای اجرای بعدی ذخیره می‌شود.
2. روی درایو در نوار کناری کلیک کنید، یا پوشه‌ای انتخاب کنید و **باز کردن / اسکن** را بزنید. مسیر جدید اسکن می‌شود؛ مسیر قبلی از نتیجهٔ ذخیره‌شده باز می‌شود و تغییرات خودکار بررسی می‌شوند. **تازه‌سازی ↻ / Refresh** فقط مسیر داخل کادر و زیرپوشه‌هایش را در پس‌زمینه بررسی می‌کند. با ورود به پوشه، مسیر کادر نیز تغییر می‌کند. مثلاً در `C:\Projects\Git-Hub`، Refresh کل درایو C را دوباره نمی‌خواند؛ فقط حجم مجموع پوشه‌های بالاتر با دادهٔ جدید محاسبه می‌شود. جدول هنگام بررسی در دسترس می‌ماند.
3. نقشهٔ فضا و جدول حجم کل زیرپوشه‌ها را نشان می‌دهند. برای ورود به یک پوشه روی نقشه کلیک کنید یا روی ردیف آن دوبار کلیک کنید.
4. از **فایل‌های بزرگ**، **فایل‌های قدیمی** و **نوع فایل‌ها** استفاده کنید. جست‌وجو زیرپوشه‌ها را هم بررسی می‌کند. فیلتر حجم، تاریخ و ترتیب نمایش در بالای جدول قرار دارند.
5. با Ctrl یا Shift چند ردیف را انتخاب کنید. **مرور حذف و کش‌های مرتبط** فهرست دقیق مسیرها و محتوایشان را برای تأیید نشان می‌دهد. کلید Delete همین پنجرهٔ تأیید را باز می‌کند. پیش‌فرض حذف دائمی است؛ انتقال به سطل بازیافت هم قابل انتخاب است.
6. پس از پاک‌سازی، اطلاعات مسیرهای مرتبط به‌روز می‌شوند؛ کارت فضای آزاد درایو نیز هر ده ثانیه تازه می‌شود. در حالت بازیافت، فایل‌ها تا خالی‌کردن سطل بازیافت در ویندوز همچنان فضای دیسک را اشغال می‌کنند.

برای آزمایش: یک مسیر را اسکن کنید و پس از ذخیره برنامه را ببندید. یک فایل آزمایشی را حذف یا جابه‌جا کنید و برنامه را دوباره باز کنید. نتیجهٔ قبلی ابتدا نمایش داده می‌شود و تغییرات در پس‌زمینه اعمال و ذخیره می‌شوند. هنگام باز بودن برنامه هم تغییرات مسیر اسکن‌شده بدون فشردن Refresh دنبال می‌شوند. فایل‌های جدید معمولاً پس از چند ثانیه دیده می‌شوند؛ تعداد زیاد تغییرات، درایو کند یا بررسی کامل زمان بیشتری می‌خواهد.

تغییرات معمول در بسته‌های کوتاه پردازش می‌شوند. در شروع، پس از ازدست‌رفتن اعلان‌های ویندوز و هر پنج دقیقه، پوشهٔ بازشده در پس‌زمینه بررسی می‌شود. کل درایو فقط زمانی بررسی می‌شود که خود ریشهٔ درایو باز باشد. Refresh دستی مسیر داخل کادر را بررسی می‌کند و بر بررسی خودکار فعال اولویت دارد. پوشهٔ بزرگ زمان بیشتری می‌خواهد، اما نتیجهٔ ذخیره‌شده قابل مرور باقی می‌ماند. اگر پوشه از دسترس خارج شود، نتیجهٔ قبلی حفظ می‌شود و بررسی به پوشهٔ بالاتر گسترش نمی‌یابد.

## آپدیت داخل برنامه

در شروع برنامه و هر شش ساعت در زمان باز بودن آن، آخرین نسخهٔ پایدار از Releases همین مخزن بررسی می‌شود. در صورت وجود نسخهٔ جدید، اعلان بالای پنجره نمایش داده می‌شود؛ **دانلود و نصب** را بزنید تا پس از دریافت و بررسی فایل، برنامه بسته و با نسخهٔ جدید باز شود. **بررسی آپدیت** در نوار کناری نیز در دسترس است. هنگام اسکن یا پاک‌سازی، نصب تا پایان عملیات غیرفعال است. دانلود را می‌توان لغو کرد.

آپدیت به اینترنت و امکان نوشتن در پوشهٔ خود برنامه نیاز دارد؛ برای استفادهٔ قابل حمل، بسته را در پوشه‌ای متعلق به خودتان استخراج کنید. اسکن‌ها و زبان در LocalAppData نگهداری می‌شوند و با تعویض فایل اجرایی از بین نمی‌روند. قطع اینترنت جلوی استفاده از برنامه را نمی‌گیرد. کاربران نسخهٔ ۱.۲ باید یک بار نسخهٔ ۱.۳ یا جدیدتر را از Releases دریافت کنند؛ اعلان آپدیت از نسخهٔ ۱.۳ فعال است.

کلیک راست روی ردیف: ورود به پوشه، نمایش در Explorer و کپی مسیر. تاریخ ایجاد و تاریخ تغییر اصلی در توضیح شناور هر ردیف نمایش داده می‌شود. خروجی CSV شامل تمام نتایج فیلترشده است؛ جدول برای پاسخ‌گویی سریع‌تر حداکثر ۲٬۰۰۰ ردیف را نمایش می‌دهد.

اگر هنگام حذف در Explorer پیام **Folder In Use** ظاهر شد، پنجره‌ها یا برنامه‌هایی را که از آن پوشه یا زیرپوشه‌هایش استفاده می‌کنند ببندید و دوباره امتحان کنید. «نمایش در Explorer» مورد انتخابی را در پوشهٔ والد نشان می‌دهد و برنامه‌های دیگر را نمی‌بندد. پایش زنده با تغییر نام یا حذف پوشه سازگار است؛ این رفتار با یک پوشهٔ آزمایشی بررسی می‌شود.

برای حذف نرم‌افزارهای نصب‌شده، صفحهٔ **برنامه‌های نصب‌شده** را باز کنید و **مرور حذف برنامه و کش** را بزنید. دستور حذف‌کننده پیش از اجرا در توضیح دکمه قابل مشاهده است؛ پاک‌سازی کش تأیید جداگانه دارد.

## رفتار اسکن و پاک‌سازی

- اسکن فقط فراداده را می‌خواند؛ فایل‌های شما را تغییر نمی‌دهد. شروع اولین اسکن با انتخاب شماست. پس از آن، نتیجهٔ بازشده به‌صورت خودکار دنبال می‌شود؛ سایر اسکن‌های ذخیره‌شده هنگام بازکردنشان بررسی می‌شوند.
- درایوهای محلی و USB آماده قابل اسکن هستند. مسیرهای شبکه پشتیبانی نمی‌شوند. هیچ محتوای فایلی به اینترنت ارسال نمی‌شود.
- حجم‌ها **منطقی** هستند و با واحدهای KiB / MiB / GiB نمایش داده می‌شوند. فشرده‌سازی، فایل‌های sparse و hard link می‌توانند باعث اختلاف با فضای اشغال‌شدهٔ واقعی شوند. hard linkها در هر مسیر شمرده می‌شوند.
- تاریخ پوشه برابر جدیدترین زمان تغییر خود پوشه یا محتوای آن است. تاریخ‌ها میلادی و به وقت محلی‌اند. قدیمی بودن یک فایل نشان‌دهندهٔ بی‌استفاده بودن آن نیست. نمای فایل‌های قدیمی از ۱۸۰ روز شروع می‌شود.
- مسیرهای غیرقابل‌دسترسی، junction، symbolic link و placeholderهای ابری با علامت ناقص گزارش می‌شوند؛ پیوندها دنبال نمی‌شوند. جزئیات حداکثر ۵۰۰ خطای اول قابل مشاهده‌اند. ردیف بدون دسترسی، اندازهٔ واقعی آن مسیر را نشان نمی‌دهد.
- اسکن قابل توقف است و نتیجهٔ متوقف‌شده واضحاً ناقص اعلام می‌شود. پاک‌سازی بر اساس اسکن متوقف‌شده فعال نمی‌شود.
- اسکن‌های پایان‌یافته به‌صورت فشرده در `%LOCALAPPDATA%\Spacio\Scans` ذخیره می‌شوند؛ خطاها و موارد بررسی‌نشده نیز حفظ می‌شوند. اسکن لغوشده نتیجهٔ کامل قبلی را جایگزین نمی‌کند. ذخیرهٔ نتیجه ممکن است بسته به تعداد فایل‌ها چند ثانیه طول بکشد و فضای دیسک مصرف می‌کند. اگر ذخیره ممکن نباشد، پیام مشخصی نمایش داده می‌شود و نتیجه در حافظهٔ همین اجرا باقی می‌ماند.
- زمان آخرین نتیجه کنار نقشهٔ فضا نمایش داده می‌شود. بررسی بدون تغییر، همان زمان و فایل ذخیرهٔ قبلی را حفظ می‌کند. نتیجهٔ خراب یا ناقص با اسکن خودکار جایگزین نمی‌شود؛ برای مسیر بدون نتیجهٔ معتبر، اسکن را بزنید. قطع دسترسی یا توقف Refresh نتیجهٔ سالم قبلی را پاک نمی‌کند. محتوای قبلاً شناخته‌شدهٔ مسیرهایی که دسترسی‌شان قطع شده حفظ و ناقص علامت‌گذاری می‌شود.
- پس از تلاش پاک‌سازی، نتیجه‌های مرتبط «تغییریافته» علامت می‌خورند و زیرشاخه‌های مربوط به‌روز می‌شوند. برای حذف بعدی، فقط موارد انتخاب‌شده پیش از نمایش جزئیات دوباره بررسی می‌شوند؛ تأیید تازه برای هر عملیات لازم است. این بررسی، وضعیت سایر بخش‌های قدیمی اسکن را معتبر اعلام نمی‌کند.
- ریشهٔ اسکن، مسیرهای سیستم و برنامه‌ها، AppData، پروفایل کاربران، محل اجرای خود برنامه و پوشه‌های حاوی موارد سیستمی یا بررسی‌نشده محافظت می‌شوند.
- قبل از انتقال، فرادادهٔ فایل یا تمام درخت پوشه با نتیجهٔ اسکن مقایسه می‌شود. تغییرات مشاهده‌شده عملیات را متوقف می‌کنند. این مقایسه قفل فایل یا snapshot اتمیک نیست؛ هنگام پاک‌سازی از تغییر هم‌زمان پوشهٔ انتخابی خودداری کنید.
- عملیات از Windows Shell و `IFileOperation` استفاده می‌کند. حالت حذف دائمی فقط پس از تأیید صریح اجرا می‌شود. در حالت سطل بازیافت، اگر ویندوز امکان بازیافت را نداشته باشد، callback حذف دائمی را رد می‌کند. سطل بازیافت خودکار خالی نمی‌شود. استثنای حفاظت AppData فقط برای مسیر دقیق کش‌های پشتیبانی‌شده است؛ کش با محتوای ناقص، پیوندی، ابری یا سیستمی پاک نمی‌شود. اسکن‌ها و تنظیمات Spacio محافظت می‌شوند.
- انتخاب هم‌زمان پوشه و فرزندش فقط یک بار پردازش می‌شود.
- زبان در `%LOCALAPPDATA%\Spacio\language.txt` ذخیره می‌شود. گزارش CSV تنها در مسیر انتخاب‌شده توسط شما نوشته می‌شود.

## Build and verification

Uses native C# / WPF and the C# compiler included with .NET Framework. No NuGet packages or downloaded SDK are needed.

Clone the repository, then build and test from its root directory:

```powershell
git clone https://github.com/aliahmadi1382/Spacio-Uninstaller.git
cd Spacio-Uninstaller
.\build.ps1
.\test.ps1

# Build/test a separate version while the previous executable remains open:
.\build.ps1 -Destination .\dist\v1.7.0
.\test.ps1 -Executable .\dist\v1.7.0\Spacio.exe
.\tools\package.ps1 -Executable .\dist\v1.7.0\Spacio.exe
.\tools\build-setup.ps1 -Executable .\dist\v1.7.0\Spacio.exe
.\tools\verify-setup.ps1 -Setup .\dist\Spacio-1.7.0-Setup.exe -ReferenceExecutable .\dist\v1.7.0\Spacio.exe
```

`test.ps1` creates isolated fixtures under `.test-data`, including a junction to another generated fixture, paths longer than 260 characters, and 10,000 empty files. Recycling and permanent-cleanup integration checks remove only generated test files/folders. Cleanup checks cover stale previews, known-cache boundaries, protected scan bytes, locked files, running owners, cancellation and command parsing without launching an uninstaller. Bilingual cleanup UI checks use generated cache fixtures under `artifacts` and test acknowledgement and cancellation. Remaining fixtures are available for inspection. Reports and off-screen Persian/English screenshots are saved to `artifacts`.

Live checks cover actual Windows create/delete/rename/resize notifications, startup reconciliation, incremental aggregate correctness, overflow fallback, cancellation, exact cache preservation and UI heartbeat responsiveness while a cache write is blocked.

Cache checks cover persistence, startup selection, offline paths, normalization, Unicode, descendant reuse, file changes, invalidation, corruption, cancellation, and atomic replacement. UI checks exercise the Refresh button against generated additions, moves, and deletions, then launch separate processes to verify automatic restoration and the actual loading-screen startup. UI checks use an isolated cache under `artifacts`, not your saved scans. Update checks cover release selection, trusted hosts, tampered packages, rollback, and a separate updater process replacing/restarting a generated application copy. No test installs over the user's app.

## Publishing updates

For each user-facing release, increment both versions in `src/AssemblyInfo.cs`, update this changelog, build, test, run `tools/package.ps1`, then `tools/build-setup.ps1` and `tools/verify-setup.ps1`. Setup embeds and verifies the exact ZIP payload; its build writes SHA256SUMS entries for both ZIP and Setup. Do not rerun packaging afterward without rebuilding Setup. Commit and push the source, tag that commit as `vMAJOR.MINOR.PATCH`, then publish a stable GitHub Release with `Spacio-MAJOR.MINOR.PATCH-win-x64.zip`, `Spacio-MAJOR.MINOR.PATCH-Setup.exe` and `Spacio-MAJOR.MINOR.PATCH-SHA256SUMS.txt`. Keep `Spacio.exe` and `Spacio.exe.config` at the ZIP root for existing updaters. Upload all assets to a draft before publishing it; the GitHub API must expose asset SHA256 digests. Keep old release assets available for rollback. Commits alone do not notify installed apps; publishing the stable release makes the update discoverable. Use the Releases/latest link when sharing the app so users always reach the newest stable version.

`verify-setup.ps1` installs only into generated Unicode fixture directories with isolated registry keys and shortcuts. It tests reinstall, optional shortcuts, collision protection, locked files, concurrent Setup, rollback after installation/uninstallation errors, downgrade rejection and real updater replacement/restart with saved-scan preservation. Real saved scans/preferences are compared read-only. It never installs over or uninstalls the user's Spacio. Use `-PublicUpgrade` with a Setup fixture built from an older payload after publication to exercise the actual release feed from a Setup installation. Installer sources are in `installer/`; the shared registration helper is `src/InstallationRegistration.cs`. Windows shortcuts use [IShellLinkW](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ishelllinkw).

After publication, `tools/verify-upgrade.ps1 -PreviousExecutable <path-to-an-older-Spacio.exe>` verifies the actual public feed, download, checksums, installation, and restart using that older release's updater. Its isolated startup smoke mode creates a saved scan with the old version and verifies restoration before live monitoring starts; the cache bytes, scan timestamp and original scanned file must remain unchanged. Use a previous version from 1.3.0 onward. The script creates isolated application copies under `.test-data`; it never replaces the supplied original executable. This integration check needs internet and a newer public release. Separate live tests verify subsequent automatic reconciliation. The loading smoke check also captures 48 rendered frames and verifies central-scene movement while the main UI thread is blocked.

Git tracks the full source, UI, translations, vector/raster brand assets, build scripts, tests, and documentation. Generated executables are distributed through Releases. Disposable test fixtures (`.test-data`), test reports/screenshots (`artifacts`), build output (`dist`), local credentials, and saved scan data are ignored. See [CHANGELOG.md](CHANGELOG.md) for version notes.

Full results navigation and minimum-size layout checks are in `src\ResultsPages.cs`.

Source files: `src\Core.cs` (scan/metadata/safety), `src\Recycle.cs` (Windows Shell interop), `src\Locales.cs` (language), `src\App.cs` (application), `src\MainWindow.xaml` (interface), `src\SelfTests.cs` (checks), `src\LiveScanner.cs` (incremental reconciliation and watcher), `src\LiveUI.cs` (live lifecycle), `src\LiveTests.cs` (live integration checks).

Brand assets: `assets\spacio.svg` and `assets\BrandMark.xaml` contain the vector leaf/storage-map mark. `tools\build-brand.ps1` renders the matching PNGs and a seven-resolution Windows ICO (16–256 px). The icon and vector mark are embedded in the executable; no separate logo file is required at runtime. The language loader also reads the prior version's saved preference when the new settings file does not exist.
